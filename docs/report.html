Get started

Ask your agent for a report from the records you provide. The default is a concise summary. Name a mode and audience when you need a particular format.

$tarosec report ./cases

$tarosec-report technical ./cases
Explain the findings for the engineering team and cite the evidence IDs.

$tarosec-report executive ./cases
Summarize the risks and decisions for management.

These are agent requests. The Python commands below are separate local helpers. If the Report specialist is missing, the entry point gives its installation selector and can provide a limited read-only summary.

npx skills add refactorroom/tarosec --skill tarosec-report

What to provide

Supply Tarosec finding, evidence, case, engagement, exercise, or simulation-result records and any referenced artifacts. Include scope, collection times, source revisions, and tool status when available. Evidence records use stable IDs to connect findings to artifacts.

Keep original evidence in an authorized location. Provide sanitized material for the intended audience and identify missing exports or collection windows.

Modes

summary
Finding counts, leading risks, coverage limits, and unresolved questions.
technical
Affected components, supported causes, evidence, remediation, and regression checks for developers.
executive
Business risks, priorities, confidence, and decisions for management.
incident
Recorded chronology, affected assets, alternate explanations, and response recommendations.
coverage
Exercise outcomes, detection and telemetry gaps, and the basis for any rate.
remediation
Prioritized actions, finding IDs, supplied ownership, and verification criteria.
compare
Changes between explicitly identified baseline and retest records.
validate
Review sources, evidence links, consistency, completeness, and provenance.

How evidence is handled

  1. Validate supplied records and reconcile IDs. Conflicting IDs and missing references remain visible as gaps.
  2. Check an artifact against its recorded SHA-256 when both are available. A matching digest establishes byte consistency with the reference. Authenticity and support for the claim still need review.
  3. Preserve severity, confidence, finding status, verification status, claim strength, incident classification, and detection outcome as separate facts.
  4. Cite the evidence and explain the limits of each conclusion. Missing evidence does not establish that an issue is absent or fixed.

Generate a local bundle

From a Tarosec checkout with Python 3.10 or later, choose a new output directory outside the input directory. The parent directory must already exist.

python3 -B skills/tarosec-report/scripts/generate_report.py \
  ./cases --type technical --output ./reports

python3 -B skills/tarosec-report/scripts/validate_report.py \
  ./reports/report.json --bundle --input ./cases

The output contains report.md, report.json, and evidence-manifest.json. The structured export omits source free text. An agent can prepare audience-specific prose after reviewing sanitized evidence.

The generator can succeed while reporting verification gaps. Validation with --bundle checks the companion files, and --input also recomputes the report from supplied records and artifacts. Use --overwrite only to replace an existing Tarosec report bundle.

Compare a baseline and retest

Provide both record IDs. When versions of the same finding differ, place them in separate snapshot directories. Exercise comparisons use a retest linked with retestOf and stable step IDs.

python3 -B skills/tarosec-report/scripts/generate_report.py \
  ./baseline --type compare --retest ./retest \
  --baseline-id CASE-BEFORE --retest-id CASE-AFTER \
  --output ./comparison

A missing retest, incompatible exercise, or unavailable supporting evidence leaves the comparison inconclusive. Absence from a later export alone does not establish a fix.

Read detection coverage

Each exercise step retains its recorded outcome, including late or partial detection, prevention, gaps, inconclusive results, and steps that did not run. The helper counts full detections, including late detections, among eligible steps with hash-matched evidence. The eligible denominator includes full and partial detections and detection gaps. Simulation-linked, prevented, unrun, inconclusive, and telemetry-gap steps are excluded.

When no steps qualify, the rate is unavailable. Interpret any rate within the supplied exercise and collection window.
